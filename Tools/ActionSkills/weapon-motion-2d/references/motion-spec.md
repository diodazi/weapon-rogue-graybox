# 动作交接规格

按任务规模选字段，不为简单动作强填整份长文。复用项目动作 ID、数据主源和术语；本表不是必须新建的引擎 API。

## 动作卡

| 字段 | 记录内容 |
|---|---|
| 身份 | 动作 ID、武器/角色、版本、设计目的、规则依据 |
| 状态 | 已确认 / 建议 / 原型试验 / 未知；不得只在文末统一说“仅供参考” |
| 来源 | 参考 ID、链接或本地文件、时间区间、已观察部分 |
| 主体与视角 | 人持武器或武器本体；侧视/俯视；面向与坐标约定 |
| 武器几何 | 刃尖、刃缘、柄端、局部原点、支点、尺度单位 |
| 运动 | 根位移、角度、支点、尖端路径、运动趋势；各项的驱动归属 |
| 时间 | 参考采样 fps、播放倍速、模拟/设计时钟、动画曝光节奏；不知道就写未知 |
| 关键姿势 | 时间、姿势意图、根位置、角度、尖端/刃向、衔接状态 |
| 事件 | 预警、有效区开闭、碰撞接触、反馈、恢复、允许派生/取消 |
| 退出 | 命中/挥空/格挡、中断、换向、落地等适用分支及现有规则依据 |
| 资产需求 | 图层/换面图/关键帧、枢轴、透明留白、相邻动作共享姿势 |
| 验证 | 实际查看或执行的预览；观察结果；尚未验证项 |

## 时间表达

若项目采用 60 Hz 逻辑时钟，1 tick 为约 16.67 ms；这不意味着必须画 60 张图/秒。画面可保持一张图多个 tick，逻辑事件仍按项目时钟发生。

使用帧区间时声明从 0 或 1 起算及边界规则。例如从 0 开始、左闭右开：预备 `[0, 8)`，生效 `[8, 11)`，恢复 `[11, 24)`。这仅演示计数方式，不是任何武器的推荐帧数；不要把它直接写进项目平衡配置。

不要用“第 3 张关键图”代替“第 3 个逻辑 tick”。视频若有慢放、补帧、变速或未知帧率，不直接据此生成精确游戏时长。

## 平面轨迹表达

对于刚性武器，可用根节点位置 R(t)、角度 θ(t) 与局部尖端 T 表达：

`tip_world(t) = R(t) + Rot(θ(t)) × T`

如果围绕局部点 P 控制旋转，显式说明 P 如何与根位置配合，不能只换 P 而让整个武器跳位。路径图中的瞬时支点和引擎的固定 Sprite pivot 也要区分。

曲线若跨过 ±180°，说明是否连续转动及转向，避免插值走了错误的短弧。插值、弹性回摆和纸片形变不自动改变受击区或物理质量。

## 关键姿势表

| 时间/阶段 | 可见姿势与意图 | 根/支点/尖端 | 运动趋势 | 游戏事件 |
|---|---|---|---|---|
| 起始 | 当前可读朝向 | 沿用前动作终态 | 延续或静止 | 读取现有规则 |
| 预备极值 | 让玩家看到方向或蓄势 | 标明反向位移或转角 | 开始释放 | 不是自动激活伤害 |
| 接触附近 | 让有效端与接触线可见 | 提供路径采样 | 峰值时机依动作而定 | 对齐有效窗口与真实接触 |
| 制动/结束 | 回到可接续状态 | 避免位置或朝向跳变 | 衰减、停住或传给下一动作 | 对齐恢复与允许衔接 |

## 检查问题

1. 暂停在起手、接触附近、结束三个位置，能否分清这是什么动作？
2. 尖端、刃缘和柄的路径是否来自同一个连续运动，而非各画各的？
3. 有效区显示与画面接触是否吻合？拖影有无误导范围或持续时间？
4. 左右镜像、挥空、碰撞、中断、连招连接是否产生突然跳位？
5. 改动是否悄悄增加追踪、扩大攻击范围或移除了原有恢复代价？
6. 当前结论是文档判断、预览观察还是实际游戏验证？交付时准确标明。
